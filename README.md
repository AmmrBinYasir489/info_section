# 🌐 WEB DEVELOPMENT – COMPLETE EXAM NOTES

---

## 1️⃣ Web Platform Constraints (Software Engineering)

**Definition:**
Web platform constraints wo limitations hoti hain jo web applications ke design, performance aur security ko affect karti hain.

### Core Constraints:

1. **Network Bandwidth**
2. **Security**
3. **Performance**
4. **Accessibility**
5. **Browser Compatibility**
6. **Scalability**

---

## 2️⃣ Bandwidth Constraint

**Meaning:**
Limited data transfer speed between client & server.

### Effects:

* Slow page loading
* Poor user experience

### Solution:

* Image compression
* Caching
* CDN

---

## 3️⃣ Performance Constraint

**Meaning:**
Web app ka slow response time.

### Causes:

* Heavy scripts
* Poor database queries

### Solution:

* Optimized queries
* Minified JS/CSS

---

## 4️⃣ Accessibility

**Meaning:**
Website har user (disabled users bhi) use kar sakay.

### Features:

* Screen reader support
* Keyboard navigation
* Alt text for images

---

## 5️⃣ Full Stack Development

**Definition:**
Frontend + Backend + Database development.

### Stack:

* Frontend: HTML, CSS, JS
* Backend: PHP
* Database: MySQL
* APIs

---

## 6️⃣ UI / UX with Server Logic

* **UI:** User interface (buttons, forms)
* **UX:** User experience
* **Server Logic:** PHP handles data & business logic

---

## 7️⃣ API (Application Programming Interface)

**Definition:**
API client aur server ke beech communication ka bridge hoti hai.

### API Request:

* GET
* POST
* PUT
* DELETE

### API Response:

* JSON / XML
* Status code (200, 404, 500)

---

## 8️⃣ Third Party APIs

**Example:**

* Google Maps API
* Payment Gateway API

### Risks:

* Data leakage
* Dependency issues

---

## 9️⃣ Cookies & Sessions

### Cookies:

* Browser side
* Small data store

### Types of Cookies:

1. Session Cookie
2. Persistent Cookie
3. Secure Cookie
4. HttpOnly Cookie
5. Third-party Cookie

### Cookie Structure:

```
name=value; expires; path; domain; secure;
```

### Session:

* Server side
* Login data store

## 🔐 WEB SECURITY & ATTACKS

---

## 🔴 SQL Injection

**Definition:**
Malicious SQL code inject karna.

**Example:**

```sql
' OR '1'='1
```

**Prevention:**

* Prepared statements
* Input validation

---

## 🔴 XSS (Cross Site Scripting)

**Definition:**
Malicious JavaScript inject karna.

**Types:**

* Stored
* Reflected
* DOM-based

**Prevention:**

* Sanitize input
* Encode output

---

## 🔴 XSRF / CSRF

**Definition:**
User se unknowingly request send karwana.

**Prevention:**

* CSRF tokens
* SameSite cookies

---

## 🔴 Authentication Attack

* Password guessing
* Credential stuffing

**Prevention:**

* Strong passwords
* CAPTCHA

---

## 🔴 Broken Authorization

**Meaning:**
Unauthorized user ko access mil jana.

**Prevention:**

* Role-based access control

---

## 🔴 Data Exposure

**Meaning:**
Sensitive data leak ho jana.

**Prevention:**

* Encryption
* HTTPS

---

## 🔴 Man in the Middle (MITM)

**Meaning:**
Client & server ke beech data intercept karna.

**Prevention:**

* SSL / TLS
* HTTPS

---

## 🔴 Insecure APIs

**Risks:**

* No authentication
* Poor validation

**Prevention:**

* API keys
* OAuth
* Rate limiting

---

## 🔴 Session Hijacking

**Meaning:**
Session ID steal kar lena.

**Prevention:**

* Secure cookies
* Session regeneration

---

## 🔴 File Upload Attack

**Meaning:**
Malicious file upload karna.

**Prevention:**

* File type check
* Rename files
* Size limit

---

## 🔴 Clickjacking

**Meaning:**
User se hidden action click karwana.

**Prevention:**

* X-Frame-Options header

---

## 🔴 DoS (Denial of Service)

**Meaning:**
Server overload kar dena.

**Prevention:**

* Rate limiting
* Firewall

---

## 🔐 Password Hashing

**Definition:**
Password ko unreadable form mein store karna.

**Example (PHP):**

```php
password_hash($pass, PASSWORD_DEFAULT);
```

---

## 🌐 Browser Isolation

**Meaning:**
Browser ko server side isolate karna to stop attacks.

## ⚙️ PHP CONCEPTS (EXAM FAVORITES)

---

## GET vs POST

| GET         | POST   |
| ----------- | ------ |
| URL data    | Hidden |
| Less secure | Secure |

---

## echo vs print

| echo            | print        |
| --------------- | ------------ |
| Fast            | Slow         |
| Multiple values | Single value |

---

## == vs === (JS / PHP)

* `==` → value compare
* `===` → value + type compare ✅

---

## include vs require

| include          | require      |
| ---------------- | ------------ |
| Warning          | Fatal error  |
| Script continues | Script stops |

### include_once / require_once

* File sirf aik baar include hoti hai

---

## Constructor vs Destructor (PHP)

```php
class Test {
 function __construct() {
  echo "Object Created";
 }
 function __destruct() {
  echo "Object Destroyed";
 }
}
```

---

## Procedural vs OOP

| Procedural | OOP      |
| ---------- | -------- |
| Functions  | Classes  |
| Simple     | Secure   |
| Less reuse | Reusable |

---

## Black Box vs White Box Testing

| Black Box          | White Box      |
| ------------------ | -------------- |
| No code knowledge  | Code knowledge |
| Functional testing | Logic testing  |
